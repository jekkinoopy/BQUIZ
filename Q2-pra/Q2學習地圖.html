D

三個值得拆開來看的關鍵機制

D-1瀏覽人次計數——「重整不加、開新頁才加」怎麼做到

  1. 機制寫在 api/db.php（每一頁都會 include 到），用 $_SESSION['total'] 當「這個瀏覽階段是否已經算過」的旗標。
  2. 只有 session 裡還沒有這個旗標時才會真的去更新資料庫：去 total 表找今天日期的那一列，有就 +1，沒有就新增一列 {date: 今天, total: 1}。
  3. 更新完立刻把 $_SESSION['total'] 設起來——同一個瀏覽階段內不管重整幾次頁面，都不會再進到「更新資料庫」那段。
  4. 畫面上「今日瀏覽」＝查今天那一列的 total；「累計瀏覽」＝對整張表做 SUM(total)。

這招（session 旗標擋重複計數＋資料庫累加）是這類乙級題目很常見的計數器寫法，記住這個模式，其他題本如果出現類似「計數器」需求可以直接套。

D-2同一種頁籤需求，程式裡出現了兩種寫法

  1. 首頁預設 4 頁籤（front/main.php）：四篇文章的完整內容全部寫死在 HTML 裡、用 CSS 藏起來（display:none），點頁籤只是切換 .active class 顯示哪一塊——整段都在前端，完全沒打 API。
  2. 分類網誌選單（front/po.php）：點分類會呼叫 getPosts(type) 打 api/get_posts.php 撈出該分類的文章標題列表；點標題再呼叫 getPost(id) 打 api/get_post.php 撈單篇內容——是真正的 AJAX 動態資料。
  3. 這兩支 JS 函式都直接寫在各自頁面的 <script> 裡，js/js.js 完全沒被用到（裡面的 lo() 函式全專案沒有任何地方呼叫）——如果你在 js/js.js 裡面找頁籤邏輯會找不到，這是正常的，不是你漏看。

學習重點：「內容固定不變、只是切換顯示」用純前端 show/hide 就好；「內容會變、來自資料庫」才需要 AJAX——之後做 Q3 的預告片按鈕列（固定 6 張圖）可以參考第一種寫法，院線片清單（會隨後台增刪）則要照第二種寫法。

D-3問卷資料流：從列表到投票到看結果

  1. front/que.php 列出 que 表裡 main_id=0 的所有列（＝題目本身），順便顯示每題的 vote 總數。
  2. 點「參與投票」進 front/vote.php，把該題目 id 的所有選項（main_id＝該題目 id 的列）列成單選按鈕。
  3. 送出後打 api/vote.php：把選中的選項那一列 vote +1，同時把它的母題目那一列 vote 也 +1（兩個地方都要更新，一個是分項統計、一個是總投票數）。
  4. front/result.php 用「該選項 vote ÷ 母題目 vote」算百分比，畫成長條圖。

這條「一張表存父子關係、送出時兩層都要更新、結果頁做百分比統計」的資料流，跟 Q3「線上訂票」的電影／場次／座位／訂單很像——差別只是 102203 用獨立資料表存訂單，不是像這裡用單一表的父子關係。
